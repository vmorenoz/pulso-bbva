# pulso-resume
Esta skill es una entrada conversacional para Pulso, no un nuevo agente ni un script autónomo. Solo actúa como LT si el agente principal efectivo es pulso; de lo contrario indica que debe seleccionarse pulso. Una skill no cambia por sí sola la identidad del agente.

Consulta status y get del Work sobre el workspace activo; nunca HOME. Recupera resultados aceptados mediante get section=results y sus report cuando sean pertinentes, junto con evidencia y readiness completo. Sigue hasMore/nextCursor en el alcance necesario. Un estado guardado no prueba agentes vivos ni ejecución actual. Un Work cerrado necesita reapertura explícita con motivo y revisión confirmada; conserva su ID e historia.

El argumento es texto natural opcional con el ID de Work y, si hace falta, una indicación de continuidad, por ejemplo `work-checkout` o `work-checkout, retoma desde las pruebas`. Para reabrir uno cerrado debe incluir el motivo. Sin argumento, retoma el foco actual solo si es inequívoco; de lo contrario pregunta cuál. No espera flags ni sintaxis de shell.

No crees un Work ni inicialices por no encontrar el solicitado. Primero confirma la existencia del Work con las tools. Si ese Work necesita contexto faltante, aplica la receta pulso-init manteniendo el mismo objetivo e ID; ante esta continuación explícita, prepare puede migrar legacy reconocido conservando respaldo; corrupción o mezcla ambigua bloquean sin sobrescribir.

Antes de repetir acciones, contrasta efectos y cambios posteriores: Explorer para lectura técnica y Executor para inspección Git con cwd de repositorio explícito y alcance de solo lectura. Pulso no usa terminal. Reasigna una capacidad ausente del rol, nunca una operación denegada. Investiga imports, APIs y comandos; pregunta solo decisiones pendientes. No reimplementes trabajo ya aceptado ni fabriques resultados para tareas antiguas.

Retoma el objetivo de entrega, no solo el último microcomando. Conserva acuerdos y autorización vigente con texto/referencia, operación, alcance y límites en el resumen confirmado del Work. «Sube el cambio» cubre commit/push normal y correcciones directamente relacionadas del mismo cambio/ticket/repositorio/rama mientras siga abierto, salvo autorización única/snapshot, retirada o nueva decisión de alcance; no concede permiso para otro objetivo ni operaciones invasivas/despliegue. Conserva el ticket del usuario o de referencia local inequívoca indicada por él; pregunta solo por ese dato si falta, no por push ya autorizado.
Un fallo CI con comando del mismo cambio activa reproducción, diagnóstico, reparación según contrato y verificación, salvo orden explícita de solo diagnóstico/read-only. Una delegación diagnóstica puede terminar sin editar, pero Pulso delega después la reparación cubierta a QA/Executor. Contrasta procedencia/diff/resultados antes de tratar cambios anteriores del mismo Work como ajenos y preserva los realmente ajenos. Reconcilia nextAction ya realizada, sin clonar el objetivo/microtareas en TODOs ni repetir acciones por estado obsoleto.
Tras cada retorno reevalúa los frentes compatibles. Un FAIL activa reparación, no desbloquea al consumidor que espera CI/publicación satisfactoria. Con publicación autorizada, delega commit/push de la corrección verificada antes de esperar su CI. Continúa hasta lograr el objetivo o depender de algo externo real sin siguiente paso autorizado, salvo pausa/cancelación del usuario; un bloqueo afecta solo sus dependientes.

Para nuevas delegaciones registra tareas y usa prepare_delegation; conserva delegation, acceptanceBasis previa y hostContext internamente. Envía a task SOLO specialistPrompt, sin envelope, schemas, paths internos ni instrucciones heredadas; añade solo contexto conversacional indispensable breve en la sección pertinente, sin duplicar restricciones. El especialista responde las tres secciones Markdown de common. Revisa el retorno y mapea status, summary y markdown literal al result compacto de accept_result, añadiendo detalles solo reales, sin inventar comandos ni inferir PASS. Usa expectedRevision actual confirmada y acceptedTaskIds explícitos para completed; para otros estados omítelos o usa []. No reconstruyas bases ni descartes resultados independientes solo por revisión global avanzada. Core genera registro y hash sin segundo informe. La tarea aceptada no acredita automáticamente criterios finales; cuando exijan evidencia formal, un observador capaz captura snapshots reales sobre la base previa conservada por Pulso, sin renovar pruebas antiguas.

Comprueba acceptanceMode: evidence (por defecto), user o both. Si el usuario confirma aceptación suficiente, usa accept_delivery con criterionIds pertinentes, source fiel y limitations; añade aceptación explícita sin reemplazar evidencia ni satisfacer su parte técnica pendiente. Si falta validación, incluida la del despliegue, pregunta proactivamente y registra validation-pending con los IDs; no inventes despliegue ni ejecución. Confirma ok:true/revisión y distingue acceptanceRecorded de closed: con closed:false conserva la aceptación y resuelve todos los issues de readiness, sin volver a pedirla ni cancelar/eliminar tareas de completedTaskIds aunque hayan vuelto a pending. Cierra naturalmente cuando proceda; pausa no es cierre.

Si la aceptación visual ya satisface el requisito acordado, retira el bloqueo visual obsoleto mediante la operación publicada salvo requisito visual separado; no la conviertas en render automatizado. Mantén pruebas pendientes y límites por criterio/frente, sin bloqueo global artificial.

Solo recibos ok:true y revisiones confirmadas actualizan el estado comunicado. Ante error o salida truncada recupera Work/resultados/evidencia, persistence y delegation/envelope/basis originales; no los reescribas a mano. Un reintento corregido requiere causa demostrada; si falla igual consulta fuentes exactas del contrato/operación y continúa acciones seguras independientes, sin repetir producto ni afirmar persistencia. accept_delivery no es idempotente. sync/recover reconcilian metadatos, no sesiones nativas. No lances automatizaciones alternativas ni cambies configuración global. Comunica avances, límites y próxima acción sin emojis.
