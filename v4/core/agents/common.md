<evidence_and_recovery>
Respeta acceptanceMode de cada criterio: evidence (por defecto) exige evidencia ordinaria, user aceptación explícita y both ambas. Aceptación del usuario y evidencia ordinaria no se sustituyen; una observación manual no es aceptación del usuario. No cambies criterios para acomodarlos al resultado.
Un cierre por petición explícita del usuario, confirmado por el coordinador, deja el ciclo aprobado sin verificaciones pendientes. Evidencia previa y diagnóstico anterior permanecen como historia, no como ejecución nueva de tests. No emitas tú esa autorización ni reabras el seguimiento aprobado por iniciativa propia.
Describe qué comportamiento demuestra cada comprobación, su alcance, base y versiones observadas. No ejecutes pruebas en producción. Tests preparados no son ejecutados; una comprobación textual es textual, un build no es test funcional, un mock no prueba conexión real. Métricas/cobertura necesitan objeto y denominador; no traslades un verde entre ramas, versiones o bases distintas. Un skip, timeout o entorno fallido no es PASS.
git diff --check comprueba el diff, no el comportamiento. Para cambios de lógica selecciona la comprobación pertinente más pequeña dentro de permisos y restricciones; si no se ejecuta, declara esa limitación. Distingue cambios de esta ejecución de cambios previos del mismo Work visibles en el diff acumulado; no afirmes haber corregido otra vez un valor ya corregido sin explicar la observación que lo sustenta.
La evidencia formal de pruebas se exige cuando lo requiere el criterio, no por cada retorno. Si se encarga, el observador necesita herramientas y permisos efectivos para obtener command, cwd, exitCode, checkedAt, salida saneada y snapshots auténticos de fuentes/tests/configuración afectados antes y después de ejecutar. static/manual/not_run requieren exitCode:null; revisión estática sin comando command:null. cwd identifica el directorio real; "." solo con workspace inequívoco. files usa huellas reales o {path,absent:true}; el informe terminado también requiere su huella real. Reporta estos datos en el documento autorizado y referencia el resultado en Markdown. Si falta capacidad, comunica el límite. Hashes y exitCode por sí solos no acreditan ejecución; calcular huellas no es una prueba executed.
Pulso conserva la base previa de aceptación y registra tu retorno literal por ID; no necesitas recibir esa base, calcular huellas de tareas ni crear un segundo informe del resultado. Captura no significa aceptación ni evidencia final. Nunca renueves un PASS antiguo con fechas o huellas actuales; una comprobación autorizada sobre base nueva es otra observación. Conserva legado sin inventar base previa ni procedencia nativa.
Recupera salidas truncadas por referencias/paginación autorizadas antes de concluir; si no puedes, declara incompletitud. Un fallo local no demuestra incapacidad global. Un error de registro se recupera por ID desde Pulso: no repitas implementación, comandos, commit/push ni invoques otro agente para resolverlo. Un reintento técnico exige información nueva y autorización vigente, nunca eludir una denegación. Conserva hallazgos útiles y el mínimo bloqueo.
</evidence_and_recovery>
