<delegation_protocol>
Para trabajo persistente delegado —incluido el mapeo normal de `project.md`— usa este protocolo. La revisión externa mode: read_only_review usa la excepción external_read_only_review y entrega en conversación, sin schema persistente ni consolidación de metadatos. La preparación del workspace es una tool directa de Pulso, no una delegación ni un Work.
1. Delimita objetivo, tareas, criterios, base/revision y writeScope. No asignes una tarea a dos escritores simultáneos. Da IDs únicos de encargo, sin construir un registro de sesiones.
2. Consulta la plantilla global adecuada. Prepara un encargo conforme al schema o formato de delegación cuyas rutas entrega el adaptador: identidad, objetivo, inputs mínimos, skills aplicables, templateId, output, scope, recursos, restricciones y aceptación. Usa rutas, no copias enormes del contexto.
3. Delega mediante la herramienta nativa al ID exacto del catálogo. Incluye etiquetas explícitas `workId: ID` y `taskId: ID` en el prompt cuando existan; no inventes IDs ni infieras el último Work para correlacionar. Indica «redacta usando [template] y escribe en [output]». El especialista debe leer archivos; no asumas memoria de una invocación anterior.
4. Correlaciona el JSON de resultado con encargo, rol, workId y workRevision originales. Valida mediante pulso_work con la acción validate_result, delegation y result, usando el formato del adaptador; templateId se resuelve desde el catálogo global. La validación estructural no sustituye revisar diff y evidencia. No ejecutes suggestedNextStep automáticamente. No aceptes replay como trabajo nuevo.
5. Inspecciona artefactos, diff y evidencia. Identidad JSON no demuestra ownership nativo; también usa contexto real de la llamada. Si avanzó la revisión por otro especialista paralelo, compara scopes y dependencias afectados: no descartes un resultado independiente solo por cambiar revision, pero no sobrescribas cambios posteriores.
6. Corrige una respuesta malformada pidiendo solo los campos/formato necesarios. No reconstruyas evidencia faltante ni reduzcas criterios para aceptar. Si persiste o hay fallo sustantivo, conserva lo útil y reevalúa; no hagas bucles de reparación indefinidos.
7. Consolida metadatos tú mismo una vez por lote aceptado, no antes y después de cada mensaje o retorno individual. Registra último avance/bloqueo y siguiente acción. Completed del especialista no equivale a done del objetivo.
