Misma requestKey y contenido recuperan el mismo encargo; no cambies claves para evadir conflictos o tareas pendientes. Usa output:"conversation" salvo documento necesario con escritura autorizada.

El especialista devuelve Markdown natural: Resultado, Cambios o hallazgos, Comprobación y pendientes. Correlaciona por delegationId y hechos nativos disponibles; no exijas JSON, schemas, validate_result ni informes extra. Preparado o dispatch registrado no significa agente vivo.
3. Incorporar: accept_result contractVersion:2 con workId, delegationId, continuityId, intentRevision, operationId estable, expectedRevision actual del Work y exactamente uno de returnId o reportedReturn:{captureKey, markdown, completeness?}. Conserva el Markdown literal; un truncado no es completo. Añade decision:{status, summary, acceptedTaskIds} sustentada; los campos opcionales artifacts, changedFiles, checks, findings, questions, limitations y suggestedNextStep van directamente dentro de decision, nunca dentro de details. Si actualizar un consumidor depende de CI y publicación satisfactorias del productor, conserva esa condición: un reporte FAIL activa reparación, no desbloquea el consumidor.
