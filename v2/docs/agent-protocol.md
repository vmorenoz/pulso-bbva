# Agent Protocol

`packages/orchestration/src/protocol/schemas.ts` is the protocol authority. It defines `TaskEnvelope` (`pulso-task/1`), `AgentResult` (`pulso-result/1`), the status enum and specialist payloads. `renderAgentProtocolInstructions` derives compact prompt instructions from that schema metadata; agent definitions do not carry a second manually maintained protocol description. The XML-like wire envelope contains XML-escaped JSON so every schema-supported field round-trips; unknown fields are rejected by strict schemas.

`parseAgentResult(result, expectedIdentity)` rejects a different protocol, delegation, specialist, Work, or WorkItem. One outer-fence removal repair is permitted; it does not rewrite fields or status aliases. `DelegationCoordinator` is a pure correlation helper: it creates envelopes, validates results, and maps statuses to binding lifecycle actions. The active host invokes its native subagent tool and Capabilities MCP; this package never starts a subagent or calls Working System directly. OpenCode's native Task does not call this TypeScript coordinator; the generated Pulso instructions are prompt-level validation guidance, not an interception or hard runtime gate.

For a completed result, Pulso registers each returned artifact with `pulso_work_artifact` before `pulso_runtime_complete(bindingId)`. If artifact registration fails, Pulso maps the delegation to `pulso_runtime_fail(bindingId)` instead of leaving an active binding. Failed, cancelled, and blocked results map respectively to `pulso_runtime_fail`, `pulso_runtime_cancel`, and `pulso_runtime_block`; no result mapping selects a retry or another specialist.

For OpenCode, the generated prompt carries the serialized canonical envelope and exact expected identity through the native Task handoff. OpenCode 1.18.32's native Task tool accepts a prompt and subagent selector but has no public JSON-Schema output parameter; it returns the child's text. SDK `session.prompt` structured output is a separate API and is not used by this runtime. Therefore the Task result must be validated against the canonical protocol instructions before Pulso chooses any terminal lifecycle operation.
