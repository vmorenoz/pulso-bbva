# Agent Protocol

`packages/orchestration/src/protocol/schemas.ts` is the protocol authority. The current breaking wire contracts are `TaskEnvelope` (`pulso-task/2`) and `AgentResult` (`pulso-result/2`). Task v2 points at result v2; result v2 gives every specialist a semantic payload. Status remains one of `completed`, `blocked`, `failed`, or `cancelled`. The XML-like wire envelope contains XML-escaped JSON; strict schemas reject unknown fields.

`SpecialistDefinition` combines the static role/tool policy with a specialist Task contract; the discriminated ResultContract is defined by the canonical Zod payload schema. `SpecialistPromptAssembler` builds programmatic canonical Tasks from the same schema/instructions used by renderers. OpenCode and VS Code still ask their LLM to formulate native tool-call arguments; the assembler is a reusable library, not a claim that either host invokes TypeScript during each model call. `ProtocolEnforcer` is host-agnostic. OpenCode applies it to native Task hooks; VS Code consumes the same prompt contracts and remains prompt-only.

For a completed Executor result, Pulso registers each returned artifact with the artifact capability before `runtime_complete(bindingId)`. After a successful bind, every branch must terminalize the binding: valid statuses use their existing lifecycle mapping; Task errors and protocol rejections call `runtime_fail` before Pulso responds. Retry/routing remains Pulso's decision. Tool IDs in OpenCode are displayed with its MCP server prefix (for example `pulso_work_create`); the MCP server's registered names are now `work_create`, `runtime_bind`, etc., removing the duplicate prefix.

Result rejection keeps detailed Zod causes on the internal error object, while the Task-facing message is capped to three concise contract issues plus a remainder count. Pulso should tell the user the delegation failed and not repeat MCP payloads, internal IDs, or validator dumps. Developers can inspect the Task error/diagnostics when needed. OpenCode `/details` toggles native tool execution detail visibility; Pulso does not patch the TUI or hide selected tools.
