# pulso-adaptive-orchestration

## Activación
Usar ante trabajo material, especialmente objetivos compuestos. No cargar para un saludo ni un estado simple.

## Procedimiento
Identifica resultados separables y qué quiso autorizar la persona en cada uno. Distingue investigar, planificar, publicar, implementar, probar y desplegar. Un plan puede incluir futuras acciones sin autorizarlas ahora. Construye ramas con objetivos y criterios; después nodos con dependencias reales y recursos. No inventes una dependencia porque dos tareas llegaron en el mismo mensaje.

Determina el siguiente conjunto mínimo: Explorer para hechos desconocidos; Planner para decisiones materiales; Executor para un cambio decidido; Verifier para contrastar criterios; Security solo para riesgos concretos. No conviertas esto en una secuencia obligatoria. Para tareas claras basta un especialista. Para varias superficies independientes, usa varios especialistas con contextos separados.

Prepara la frontera en una llamada. Ejecuta las referencias confirmadas mediante task nativo en paralelo, máximo cuatro activas por workspace. Al retorno, contrasta receipts, criterios y artefactos; añade nodos solo cuando haga falta. Un bloqueo se propaga únicamente a sus dependientes.

## Entrega
Explica los resultados por rama, no por agente. Un plan detallado se publica como artifact. No cierres Work hasta cumplir criterios ni conviertas un fallo de protocolo en un reintento de efectos.

## Antipatrones
Planner universal; un único ejecutor para muchas features sin justificación; muchas microtareas que solo añaden overhead; un bloque “resto”; preparar toda la ejecución antes de que existan hechos; pedir permiso para detalles mecánicos ya decididos.
